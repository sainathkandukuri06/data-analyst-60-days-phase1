# Day 22 – SQL JOINs (Combining Data from Multiple Tables)


## 1. What is a SQL JOIN?

A SQL JOIN is used to combine rows from two or more tables based on a related column between them.

In real-world databases, information is usually stored in separate tables to reduce data duplication and improve database organization.

For example:
- Customers table stores customer information.
- Orders table stores order information.
- Products table stores product information.
- Payments table stores payment information.

JOINs help us retrieve related information from these tables.

### Example

**Customers Table**

| customer_id | customer_name | city |
|---|---|---|
| 101 | Sainath | Hyderabad |
| 102 | Rahul | Chennai |
| 103 | Priya | Bangalore |
| 104 | Kiran | Mumbai |

**Orders Table**

| order_id | customer_id | amount |
|---|---|---|
| 501 | 101 | 2500 |
| 502 | 102 | 3000 |
| 503 | 101 | 1500 |
| 504 | 103 | 4000 |

The `customer_id` column connects both tables.

---

## 2. Why Do We Need SQL JOINs?

JOINs are important because:

1. They combine information from multiple tables.
2. They reduce unnecessary data duplication.
3. They help generate business reports.
4. They make database analysis easier.
5. They help identify missing or unmatched records.

### Real-World Applications

- Finding customers who purchased products.
- Calculating revenue generated by each customer.
- Identifying customers who never placed orders.
- Analyzing employee and department information.
- Generating sales performance reports.

---

## 3. Types of SQL JOINs

There are five major JOIN types:

1. INNER JOIN
2. LEFT JOIN
3. RIGHT JOIN
4. FULL OUTER JOIN
5. CROSS JOIN

SELF JOIN is another important technique.

---

## 4. INNER JOIN

### Definition

INNER JOIN returns only the records that have matching values in both tables.

### Syntax

```sql
SELECT columns
FROM table1
INNER JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    c.customer_name,
    o.order_id,
    o.amount
FROM Customers c
INNER JOIN Orders o
ON c.customer_id = o.customer_id;
```

### Output

| customer_name | order_id | amount |
|---|---|---|
| Sainath | 501 | 2500 |
| Rahul | 502 | 3000 |
| Sainath | 503 | 1500 |
| Priya | 504 | 4000 |

**Key Point:** Customers without matching orders are excluded.

### Business Use Cases

- Finding customers who purchased products.
- Combining sales and product information.
- Identifying employees assigned to projects.

---

## 5. LEFT JOIN (LEFT OUTER JOIN)

### Definition

LEFT JOIN returns all records from the left table and matching records from the right table.

If there is no matching record, the right-side columns contain NULL.

### Syntax

```sql
SELECT columns
FROM table1
LEFT JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    c.customer_name,
    o.order_id,
    o.amount
FROM Customers c
LEFT JOIN Orders o
ON c.customer_id = o.customer_id;
```

### Important Business Example

Find customers who have never placed an order.

```sql
SELECT
    c.customer_id,
    c.customer_name
FROM Customers c
LEFT JOIN Orders o
ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;
```

**Key Point:** LEFT JOIN is useful for identifying missing or unmatched records.

---

## 6. RIGHT JOIN (RIGHT OUTER JOIN)

### Definition

RIGHT JOIN returns all records from the right table and matching records from the left table.

If there is no match, the left-side columns contain NULL.

### Syntax

```sql
SELECT columns
FROM table1
RIGHT JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    e.employee_name,
    p.project_name
FROM Employees e
RIGHT JOIN Projects p
ON e.employee_id = p.employee_id;
```

**Key Point:** RIGHT JOIN preserves all records from the right-side table.

---

## 7. FULL OUTER JOIN

### Definition

FULL OUTER JOIN returns all records from both tables.

It includes:
- Matching records.
- Unmatched records from the left table.
- Unmatched records from the right table.

### Syntax

```sql
SELECT columns
FROM table1
FULL OUTER JOIN table2
ON table1.common_column = table2.common_column;
```

### Example

```sql
SELECT
    c.customer_name,
    o.order_id
FROM Customers c
FULL OUTER JOIN Orders o
ON c.customer_id = o.customer_id;
```

**Key Point:** Useful for comparing datasets and identifying missing records.

**Note:** PostgreSQL and SQL Server support FULL OUTER JOIN. MySQL does not support it directly. It can be simulated using LEFT JOIN, RIGHT JOIN and UNION.

---

## 8. CROSS JOIN

### Definition

CROSS JOIN returns every possible combination of rows from two tables.

### Syntax

```sql
SELECT columns
FROM table1
CROSS JOIN table2;
```

### Example

```sql
SELECT
    c.color,
    s.size
FROM Colors c
CROSS JOIN Sizes s;
```

If Table 1 contains 2 rows and Table 2 contains 3 rows:

Total combinations = 2 × 3 = 6.

### Formula

Total Rows = Rows in Table 1 × Rows in Table 2

**Key Point:** CROSS JOIN is useful for generating combinations and test datasets.

---

## 9. SELF JOIN

### Definition

SELF JOIN means joining a table with itself.

It is useful when records in the same table are related to one another.

### Example: Employee and Manager

```sql
SELECT
    e.employee_name AS Employee,
    m.employee_name AS Manager
FROM Employees e
LEFT JOIN Employees m
ON e.manager_id = m.employee_id;
```

### Explanation

- `e` represents the employee.
- `m` represents the manager.
- Both aliases refer to the same Employees table.
- `manager_id` connects employees to their managers.

### Applications

- Employee-manager relationships.
- Organizational hierarchies.
- Parent-child relationships.

## 10. Primary Key and Foreign Key

### Primary Key

A Primary Key uniquely identifies every record in a table.

Properties:
- Contains unique values.
- Cannot contain NULL values.
- Each table has one primary key constraint, which can contain multiple columns.

### Foreign Key

A Foreign Key references a candidate key, typically the Primary Key, in another table.

Example:

Customers:
- customer_id → Primary Key.

Orders:
- order_id → Primary Key.
- customer_id → Foreign Key referencing Customers.

### Database Relationships

| Relationship | Description |
|---|---|
| One-to-One | One record relates to one record |
| One-to-Many | One record relates to multiple records |
| Many-to-Many | Multiple records relate to multiple records |

## 11. How SQL JOINs Work Internally

When a SQL JOIN query is executed, the database generally performs these operations:

1. Query Parsing – Checks SQL syntax and structure.
2. Query Validation – Checks tables, columns and permissions.
3. Query Optimization – Selects an efficient execution strategy.
4. JOIN Execution – Finds matching records.
5. Result Generation – Returns the requested output.

### Common JOIN Algorithms

**Nested Loop Join:** Compares rows from one input against rows from another input.

**Hash Join:** Uses a hash table to find matching records, commonly for equality joins.

**Merge Join:** Matches records from suitably ordered inputs.

The database optimizer chooses an appropriate execution strategy based on factors such as table size, indexes and available statistics.

## 12. Important SQL JOIN Rules

### Rule 1: Use Table Aliases

```sql
SELECT c.customer_name
FROM Customers c;
```

Aliases improve readability.

### Rule 2: Specify the Correct JOIN Condition

```sql
ON c.customer_id = o.customer_id
```

Incorrect conditions can generate incorrect results.

### Rule 3: Understand Duplicate Rows

If one customer has five orders, the JOIN can return five rows for that customer.

This is expected one-to-many relationship behavior.

### Rule 4: Understand NULL Values

NULL represents missing or unknown information.

Use:

```sql
WHERE column_name IS NULL;
```

or:

```sql
WHERE column_name IS NOT NULL;
```

### Rule 5: Understand ON vs WHERE

The ON condition controls matching during the JOIN.

The WHERE condition filters the resulting rows.

This distinction is especially important when using LEFT JOIN.

## 15. Key Takeaways

| Concept | Important Point |
|---|---|

| SELF JOIN | Joins a table with itself |
| Primary Key | Uniquely identifies records |
| Foreign Key | References a key in another table |
